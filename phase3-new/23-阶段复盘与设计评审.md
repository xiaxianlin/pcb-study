# 第 23 章 · 阶段复盘与设计评审

> **所属阶段**：阶段三 · 单片机与第一块项目板
> **前置课程**：第 17～22 章
> **本课难度**：⭐⭐

## 本章目标

学完本章，你应该能够：

1. 用一张评审清单覆盖原理图、PCB、BOM、测试四类问题。
2. 组织一次 30～60 分钟的设计评审，并记录结论。
3. 区分“必须改”“建议改”“接受风险”三级问题。
4. 用 FMEA/风险矩阵给问题排优先级。
5. 把评审结论转成改版任务和验证计划。
6. 复盘阶段三的学习成果，找出下一个短板。
7. 说出至少 8 个评审常见坑。

设计评审不是“挑毛病大会”，是“在投板前用别人的眼睛找自己的盲区”。评审记录比评审本身更重要。

## 正文

### 23.1 它解决什么问题：三个真实场景

#### 场景一：评审只看了原理图，PCB 封装错了

评审会上大家对着原理图讨论，没人打开 PCB 看封装。投板后发现 USB 座封装反了。评审要覆盖“图—板—料—测”四块。

#### 场景二：问题记了一堆，没人闭环

评审记录写了 20 条，改版时只改了 5 条，剩下的又带到下一版。每条问题要有责任人/截止/验证方式。

#### 场景三：评审变成“领导拍板”

没有清单，靠个人经验，漏掉电源余量/ESD/测试点。评审要有固定清单和分级。

#### 23.1.1 场景一展开：评审只看了原理图

很多团队的“评审”实际只做了一件事：把原理图投到屏幕上，从第一页翻到最后一页，问“这里对不对”“这个电容干嘛的”。看起来每个网络都看过了，但没有人把封装、焊盘、丝印、BOM 和结构放在一起核对。结果打样回来，芯片是 QFN 封装，原理图符号却按 LQFP 画的，引脚编号整体错位；或者连接器选了卧式，结构图要求立式，装不进外壳。这类问题在原理图阶段“看不出来”，因为原理图只表达电气连接，不表达物理尺寸。真正的评审必须把“图纸—封装—实物—结构”四条线并在一起看：原理图每个器件是否有对应封装、封装焊盘与器件手册是否一致、1 脚方向与丝印是否一致、连接器高度与外壳是否干涉、BOM 里的型号是否能买到。只翻原理图的评审，通过率很高，但打样返工率也很高；它不是评审，是“集体看了一遍图”。

**怎么改**：评审材料里必须包含“封装核对表”和“1:1 打印图”；每个连接器、每个极性器件、每个非常规封装都要单独列一行，写清“手册页码/焊盘尺寸/1 脚方向/装配高度”。评审时随机抽 5 个器件，让设计者当场翻手册核对；抽到错的，说明自查没做，整批退回重查。这个动作很“笨”，但能拦住大部分“封装错、方向错、装不上”的问题。

#### 23.1.2 场景二展开：问题记了一堆，没人闭环

另一种常见情况：评审开了三小时，白板上写满问题，大家拍照、鼓掌、散会。两周后打样回来，同样的问题还在；问“上次那个 RS485 终端加了吗”，回答“太忙了，忘了”。问题不是“没发现”，而是“发现了没人跟”。根因通常有三个：没有责任人（写“硬件组”等于没人）、没有期限（写“尽快”等于无限期）、没有验证（改没改、改对没改，没人确认）。于是问题表变成“许愿池”，每次评审重新捞一遍，团队逐渐不相信评审有用，下一次就真的走过场了。

**怎么改**：问题表只允许“具体人+具体日期+可验证结果”三列同时存在，缺一列就不算记录；每周固定 15 分钟过表，延期要说明原因和新日期；关闭必须有证据（复测数据、波形、照片、Gerber 截图），不能口头说“改好了”。主持人下次评审的第一页，就是上次问题表的关闭情况；没关闭的，先处理再开新评审。这样问题表才是“账本”，不是“备忘录”。

#### 23.1.3 场景三展开：评审变成“领导拍板”

还有一类评审，技术讨论还没开始，领导先说“我看这个方案可以，就这样吧”。后面的人要么附和，要么沉默；不同的意见被解读为“不配合”。评审结论变成了“领导意志”，风险没有被真正讨论。更糟的是，一旦后面出问题，没人敢说是“当时提过但被压下去”的，复盘也复不出真因。

**怎么改**：把“技术结论”和“资源决策”分开。技术评审由主持人按清单问，评审人只对“事实/风险/证据”负责；领导最后听结论，做“资源/进度”决策，不提前定调。会议开始前明确“今天先不谈进度，只谈风险”；记录员把“谁提出了什么风险、是否被接受”写进纪要。这样即使决策者选择“接受风险”，也是“有记录的接受”，而不是“没人知道的风险”。评审的价值不是“统一思想”，是“把风险摆到桌面上”。
### 23.2 它是什么：四块清单 + 三级结论

四块：

1. **原理图**：电源、复位、时钟、接口、保护、ERC。
2. **PCB**：布局、地、差分、晶振、电源、DRC、丝印。
3. **BOM/生产**：封装、替代料、钢网、坐标、测试点。
4. **测试**：Bring-Up、功能、环境、可靠性。

三级结论：

- **P0 必须改**：会导致不工作/损坏/无法生产。
- **P1 建议改**：影响可靠性/成本/可维护性。
- **P2 接受风险**：记录原因，下一版再改。

> **术语第一次出现**：风险矩阵（risk matrix）用“严重度×发生概率”给问题分级，决定先改什么。

#### 23.2.5 需求清单：逐项写法

| 项 | 要写清 | 验收方式 |
|---|---|---|
| 输入电源 | 电压范围/电流/接口 | 可调电源实测 |
| 输出 | 路数/电压/电流/纹波 | 电子负载+示波器 |
| 主控 | 型号/主频/存储 | 读 ID/跑程序 |
| 通信 | 协议/速率/节点数 | 收发/误码统计 |
| 人机 | 按键/指示/显示 | 逐项操作 |
| 环境 | 温度/湿度/防护 | 温箱/喷淋 |
| 结构 | 尺寸/安装/接口位置 | 卡尺/3D |
| 成本 | BOM 目标/打样预算 | 询价对比 |
| 时间 | 打样/小批/量产 | 里程碑 |
| 认证 | CE/FCC/CCC/UL | 送检计划 |

**写法**：每条都要“数值+条件+验收人”；写不出数值，说明需求还没定。

**边界**：明确“不做什么”，比如不做无线、不做外壳，防止后期加需求。

**变更**：需求变更要记录影响（成本/进度/重评）。

#### 23.2.6 设计清单：逐项写法

| 项 | 自查问题 | 证据 |
|---|---|---|
| 电源树 | 每路来源/负载/余量 | 预算表 |
| 去耦 | 每个电源脚有电容 | 原理图截图 |
| 复位 | 上电/按键/看门狗 | 波形 |
| 时钟 | 晶振/负载电容/频偏 | 波形/说明 |
| 接口 | 电平/终端/ESD | 图+计算 |
| 保护 | 反接/过压/过流 | 图+选型 |
| 热 | 功耗/温升/散热 | 计算/实测 |
| PCB | 层叠/线宽/地 | 叠层+DRC |
| 结构 | 板框/高度/连接器 | 3D/1:1 |
| 测试 | 测试点/调试口 | 图 |

**用法**：每条都要有“证据”；没有证据的“已检查”不算。

**优先级**：电源/时钟/复位/接口是“板子活不活”的四根柱子。

#### 23.2.7 测试清单：逐项写法

| 项 | 条件 | 判据 | 样本 |
|---|---|---|---|
| 上电电流 | 空载/满载 | 在预算内 | 全检 |
| 电源纹波 | 20MHz 带宽 | <规格 | 3 块 |
| 复位时序 | 上电/掉电 | 脉宽/电平 | 3 块 |
| 通信 | 最坏负载 | 误码率 | 3 块 |
| 高低温 | -40/+85℃ | 功能正常 | 3 块 |
| 温循 | 5～20 次 | 无虚焊 | 3 块 |
| 振动 | 扫频/随机 | 无松动 | 3 块 |
| ESD | ±4/±8kV | 不死机 | 3 块 |
| 老化 | 24～168h | 无早期失效 | 5 块 |

**写法**：判据必须是数字/波形/现象；不能写“正常”。

**记录**：实测值/照片/波形；与判据一一对应。

#### 23.2.8 生产清单：逐项写法

| 项 | 检查 | 责任 |
|---|---|---|
| BOM | 型号/封装/位号/替代 | 硬件 |
| Gerber | 层数/线宽/阻焊/字符 | 硬件 |
| 钻孔 | 孔径/槽孔/过孔 | 硬件 |
| 坐标 | 原点/旋转/镜像 | 硬件 |
| 钢网 | 厚度/开孔/拼板 | 工艺 |
| 拼板 | 间距/工艺边/Mark | 工艺 |
| 测试 | 测试点/治具/FCT | 测试 |
| 首件 | 核对/签字/封样 | 质量 |
| 包装 | 静电/缓冲/标签 | 生产 |

**顺序**：BOM→Gerber→钻孔→坐标→钢网→拼板；任何一项改动都要重出。

**课程**：生产清单是“给工厂看的”，不是“给自己看的”。

#### 23.2.9 四块清单的使用顺序

评审不是四块一起上，而是有顺序：先需求，再设计，再测试，最后生产。顺序错了会浪费很多时间——需求还没定清楚就讨论 PCB 线宽，等于在流沙上盖房子；测试判据还没写就讨论生产测试点，最后一定返工。正确顺序是：先确认“要做对什么”（需求），再确认“怎么做”（设计），再确认“怎么证明做对了”（测试），最后确认“怎么造出来”（生产）。每一块内部也有顺序：需求先电源/接口/环境，设计先电源/时钟/复位/接口，测试先功能/电源/信号，生产先 BOM/Gerber/坐标。按顺序过，前面的结论能直接约束后面，评审效率最高。

**反例**：一上来就讨论丝印字体、外壳颜色，花了半小时，电源余量却没算。这种评审“很热闹”，但关键风险没碰。

#### 23.2.10 清单怎么维护才不过时

清单不是写完就锁进抽屉。每次评审发现的新问题，如果属于“下次还会犯”，就应在 24 小时内变成清单的一条；如果是“这个项目特有”，就记在项目风险表，不进通用清单。清单每季度清理一次：合并重复项、删掉已经不可能发生的、把“建议”升级成“必须”。清单条目要写“检查动作”，不要写“注意电源”——前者可执行，后者是口号。一个团队如果半年后清单还是最初那 30 条，说明要么没评审，要么没人总结；真正用起来的清单，一定在长胖和瘦身之间反复。

**做法**：给每条清单加“来源”（哪次评审/哪个客诉），评审时看到同类问题能追溯；新条目先试用两次，再决定是否固化。
### 23.3 关键检查项

| 类别 | 检查项 | 判据 |
|---|---|---|
| 电源 | 余量/散热/去耦 | 峰值×1.3 |
| 复位 | RC/按键/BOOT | 按手册 |
| 时钟 | 晶振/负载电容/包地 | 起振 |
| 接口 | ESD/差分/终端 | 协议 |
| PCB | 地/跨分割/DRC | 清零 |
| BOM | 封装/替代料 | 可采购 |
| 测试 | 测试点/文档 | 可复现 |

#### 23.3.5 逐章复盘：第 17～22 章要看什么

**17 单片机基础**：GPIO 推挽/开漏、上拉/下拉、ADC 采样时间与源阻抗、定时器/PWM、中断/DMA、外设保护。评审时问“按键有没有消抖/上拉多大/ADC 源阻抗多少”。

**18 STM32 最小系统**：电源域/去耦、BOOT0、复位、晶振负载电容、SWD、USB、上电时序。评审时问“BOOT0 上电时是什么电平/晶振负载电容选了多少”。

**19 2 层板实战**：叠层/线宽/过孔/地/差分/扇出/丝印/DRC/Gerber。评审时看“地是否连续、电源线够不够宽、Gerber 逐层对不对”。

**20 Bring-Up**：静态检查、限流上电、电流预算、故障树、上电时序、记录表。评审时问“首板有没有限流/有没有记录/异常怎么定位”。

**21 测试与可靠性**：测试计划/判据、温循/振动/EMC/老化、降额、失效分析、报告。评审时问“判据是数字吗/样本几块/失效闭环了吗”。

**22 开源工程**：Arduino Uno R3 / OrangePi Zero H3 / CM4IO / BeagleBone Black 的电源/接口/布局可借鉴点。评审时问“我们的方案和参考设计差在哪”。

**用法**：逐章复盘不是“再讲一遍”，是“拿这一章的问题清单去问当前项目”。

#### 23.3.6 项目复盘：2 层控制板的评审实录

**背景**：12V 输入、5V/3.3V、STM32、继电器、RS485、按键/指示灯，2 层板 100×80mm。

**评审发现 1**：继电器线圈与 MCU 共地，但没有续流二极管靠近线圈；结论“有条件通过”，要求加 SS34 并挪到连接器旁。

**发现 2**：RS485 终端电阻只在主站侧，从站没留；要求加跳线/焊盘可选。

**发现 3**：3.3V LDO 输入 5V、输出 200mA，功耗 (5-3.3)×0.2=0.34W，SOT-23 温升偏高；改成 SOT-89 并加铜。

**发现 4**：Type-C 只有 CC1/CC2 下拉，没有 ESD；加 TVS 阵列。

**发现 5**：测试点只有电源，没有复位/时钟/SWD；补 4 个测试点。

**结论**：Conditional；5 项闭环后打样；责任人/3 天。

**课程**：真实评审的价值，是“在打样前发现这 5 条”。

#### 23.3.7 评审现场怎么走

**动线一：按页走**。适合原理图，逐页看，每页问“这页做什么/电源从哪来/信号去哪/有没有保护”。

**动线二：按信号链走**。从输入连接器→保护→滤波→转换→主控→输出→负载，沿一条链看，容易发现“中间断点/电平不匹配”。

**动线三：按电源树走**。从输入→DCDC/LDO→各电源域→负载，看每路电流/余量/去耦/上电时序。

**动线四：按最坏情况走**。最高温/最低压/最大负载/最差线缆，问“这时还成不成”。

**用法**：一场评审选 1～2 条动线，不要“想到哪看到哪”。动线走完，再回到清单补漏。

#### 23.3.8 问题的四种类型

**事实型**：“这个电容没接”“这个网络名拼错”——直接改，不需要讨论。

**风险型**：“这个 LDO 功耗可能超”“这个地可能跨分割”——要算/要测，给结论。

**取舍型**：“加 TVS 成本上升”“四层板贵 30%”——要决策者拍板，记录接受人。

**未知型**：“这个器件高温下参数不知道”——要查手册/做实验，给期限。

**处理**：事实型当场改；风险型给数据；取舍型记录决策；未知型转任务。把四类混在一起讨论，会议一定低效。

#### 23.3.9 评审的边界：哪些不该在会上解决

评审不是“所有问题的解决方案现场”。三类问题不该在评审会上展开：一是需要长时间计算/仿真的（如环路稳定性、SI 仿真），应会后给结论；二是需要实验验证的（如温升、EMC），应列任务；三是纯资源/进度决策（加不加人、延不延期），应由决策者另开。评审会只做三件事：确认事实、评估风险、定结论/责任人。把技术计算和资源博弈塞进评审，会议一定超时，而且结论质量差。

**判断**：如果一个问题 10 分钟内无法用现有数据说清，就转任务；如果它影响 Go/No-Go，就定“关闭条件”，而不是现场猜答案。

#### 23.4.4 评审流程的六个环节

**一、自检**：设计者按四块清单自查，把“已知问题”先写出来。自检不是“我觉得没问题”，而是逐条填证据。

**二、材料**：提前 3 天发原理图、PCB、BOM、测试报告、风险表、问题闭环表；材料不全就改期，不要“边讲边找”。

**三、逐项**：按清单过，只花时间在“没过的/有风险的/有争议的”；已经过的项一句话带过。

**四、讨论**：每个问题定性（安全/功能/外观）、影响（成本/进度）、方案（改设计/改工艺/接受）；不跑题、不翻旧账。

**五、结论**：当场给 Go / Conditional / No-Go；Conditional 要写清关闭项、责任人、期限、验证方法。

**六、归档**：记录签字、扫描归档、问题进跟踪表；下次评审先看上次关闭情况。

**时间控制**：1～2 小时；超过就拆成“原理图评审”和“PCB 评审”两场。

**课程**：没有结论的评审，等于没开；没有归档的评审，等于没发生。

#### 23.4.5 风险矩阵：怎么打分才有意义

**严重度 S**：1=无影响，3=功能降级，5=安全/起火/批量报废。

**发生度 O**：1=几乎不可能，3=偶尔，5=大概率（新设计/新工艺/新器件）。

**探测度 D**：1=测试能稳定发现，3=要专门测，5=现有测试发现不了。

**RPN**：`S×O×D`；>100 必须处理，50～100 要有措施，<50 可接受但记录。

**例子**：电源反接无保护（S5/O3/D4=60）；丝印方向错（S2/O3/D2=12）；晶振负载电容错（S3/O4/D4=48）。

**用法**：先处理“高 S”，再看 RPN；安全项不看分数，一票否决。

**课程**：打分是排序工具，不是精确科学；目的是“有限时间花在刀刃上”。

#### 23.4.6 问题闭环表：从记录到关闭

| 字段 | 写法 | 作用 |
|---|---|---|
| 编号 | R-001 | 唯一、可引用 |
| 问题 | 一句话描述现象 | 不写“有问题” |
| 位置 | 页/位号/网络 | 能定位 |
| 严重度 | 高/中/低 | 排序 |
| 责任人 | 具体人 | 不写“大家” |
| 期限 | 日期 | 可考核 |
| 措施 | 改什么/怎么改 | 可执行 |
| 验证 | 怎么证明改好了 | 可判定 |
| 状态 | 打开/关闭/延期 | 可跟踪 |

**关闭条件**：有验证证据（复测数据/波形/照片），不是“改完了”。

**延期**：要写原因/新期限/风险接受人。

**课程**：闭环表的每一列，都是防止“问题消失”的钉子。

#### 23.4.7 复盘会：怎么开出不伤人的真话

**开场**：主持人先定调“对事不对人，目的是下一块板更好”。

**数据先行**：进度/成本/返修/测试数据摆出来，减少“互相印象”。

**顺序**：先讲“做对的”（可复制），再讲“做错的”（可改进），最后讲“下一步”。

**发言**：每人 3 分钟，不打断；记录员只记事实和决定。

**深挖**：用 5Why，问到“流程/规范”层，不停在“某某粗心”。

**输出**：3 条经验、3 条改进、责任人、时间；下次会议第一项检查。

**课程**：复盘开成追责会，下一次就没人说真话了。

#### 23.4.8 评审提问：二十个“一句话问到点上”

1. 这路电源最坏负载多少？余量多少？
2. 这个 LDO 功耗多少？封装能散掉吗？
3. 上电时 BOOT0 是什么电平？
4. 复位脉宽够不够？掉电时会不会误复位？
5. 晶振负载电容按多少选的？频偏测过吗？
6. 这个接口电平匹配吗？共地吗？
7. ESD 打哪里？TVS 结电容影响信号吗？
8. RS485 终端/偏置在哪？从站留了吗？
9. 地去哪了？有没有跨分割？
10. 电源线多宽？过孔几个？
11. 差分对等长吗？参考面连续吗？
12. 这个连接器高度和外壳干涉吗？
13. 测试点在哪？探针够得着吗？
14. 最坏温度下参数漂移多少？
15. 这个器件降额多少？
16. 失效了怎么定位？有测试点吗？
17. BOM 有替代料吗？交期多少？
18. Gerber 逐层看过吗？钻孔对得上吗？
19. 首件谁签？封样了吗？
20. 这次评审的问题，谁跟到关闭？

**用法**：不需要全问；按项目风险挑 5～8 个。

#### 23.4.9 评审记录：一页纸模板

**抬头**：项目/版本/阶段/日期/参会。

**结论**：Go / Conditional / No-Go（一句话）。

**条件**：编号/关闭项/责任人/期限（表格）。

**风险**：高/中/低+影响+接受人。

**决定**：改设计/改工艺/接受/加测试。

**签字**：主持人/设计者/决策者。

**附件**：原理图截图/PCB 截图/测试数据。

**课程**：一页纸能说清，才说明评审真的开过。

#### 23.4.10 评审与变更：ECO 怎么走

**触发**：评审问题/测试失效/物料替代/客户需求。

**评估**：影响范围（原理图/PCB/BOM/结构/测试/认证）。

**评审**：高风险变更重新过清单；低风险走简化审批。

**实施**：改图/改版/改工艺；版本号。

**验证**：针对变更项复测；回归相关项。

**归档**：ECO 单/变更记录/验证报告。

**课程**：变更不重评，等于把风险直接放行。

#### 23.4.11 评审工具：边界图与 DFMEA

**边界图**：把系统画成“输入—处理—输出—环境—人”，标出接口和外部依赖。评审时看“每个接口有没有定义/保护/测试”。

**DFMEA**：对每个功能列“失效模式—后果—原因—现行控制—S/O/D—措施”。它比“凭经验挑问题”系统，但费时间；关键子系统（电源/通信/安全）值得做。

**检查表**：把历史问题变成勾选项；最快、最实用。

**用法**：小项目用检查表；复杂/安全相关加边界图+DFMEA；不要为了“显得专业”全上。

#### 23.4.12 评审中的“三不”原则

**不跑题**：问题超出本次范围，记下来另开；不要在现场展开新设计。

**不翻旧账**：只讨论当前版本；历史问题进复盘，不进评审。

**不追责**：评审是找风险，不是找责任人；责任在复盘/绩效环节。

**主持人职责**：有人跑题就拉回；有人被攻击就制止；时间到了就收结论。

**课程**：三不做不到，评审会变成“吵架/聊天/批斗”。

#### 23.4.13 主持人手册：一场评审怎么控

开场先说规则：只讨论当前版本、只对事、每个问题 10 分钟、结论三种。然后按动线走，遇到跑题就说“记下来，会后单独聊”；遇到人身攻击就说“我们回到数据”；遇到“这个以前都这样”就问“以前的失效数据呢”。每到 30 分钟看一次剩余高风险项，必要时砍掉低优先级。最后 10 分钟必须收结论：Go/Conditional/No-Go，条件/人/日期，当场复述一遍让记录员确认。主持人不是“技术最强的人”，而是“让会议产出结论的人”。

**自检**：会后问自己三个问题——高风险项都聊到了吗？每个问题有人跟吗？结论能被执行吗？

### 23.5 选型与降额

评审不是“越严越好”，要按产品定位：

| 产品 | P0 门槛 | 说明 |
|---|---|---|
| 学习板 | 能亮/能下载 | 允许飞线 |
| 小批量产品 | 功能/安规/可生产 | 不能飞线 |
| 工业/医疗 | 可靠性/认证 | 全项 |

#### 23.5.1 评审门禁：五个节点

**门禁 1（需求→原理图）**：需求清单齐、接口/电源/环境明确、成本/时间可行。不过门禁就画图，后面一定返工。

**门禁 2（原理图→PCB）**：ERC 通过、封装核对、电源预算、时钟/复位/接口/保护自查完。这一关能拦住“封装错/电源不够”。

**门禁 3（PCB→打样）**：DRC/飞线、Gerber 逐层、叠层/线宽/过孔、丝印/极性、拼板/工艺边、测试点。这一关能拦住“板子做出来不能焊/不能测”。

**门禁 4（首板→小批）**：Bring-Up 通过、电流/温升/波形正常、关键功能全过、问题闭环。这一关能拦住“设计缺陷进批量”。

**门禁 5（小批→量产）**：测试报告齐、环境/EMC 过、BOM/替代/交期确认、治具/产能就绪。这一关能拦住“量产翻车”。

**例外**：任何跳门禁都要书面批准，写清风险与补救；不能“口头说没事”。

**课程**：门禁不是流程负担，是把返工成本从“批量”压到“图纸”。

#### 23.5.2 文档与追溯：评审留下什么

**评审记录**：结论/条件/风险/签字；一页纸。

**问题闭环表**：编号/责任人/期限/验证/状态。

**风险表**：S/O/D/RPN/措施/接受人。

**测试报告**：条件/数据/判据/结论。

**变更记录（ECO）**：改什么/为什么/影响/验证。

**归档结构**：项目/阶段/日期/版本；文件名可读。

**追溯链**：需求→设计→测试→问题→变更→验证，任一环能倒查。

**课程**：文档不是给别人看的，是给三个月后的自己看的。

#### 23.5.3 评审失败的六种典型

**走过场**：材料不齐、时间 20 分钟、只签字。后面用返修买单。

**一言堂**：领导先定调，评审人不敢说话；风险被“同意”掩盖。

**只挑刺**：只说过错，不给方案/优先级；设计者进入防御，讨论失效。

**无结论**：讨论两小时，没人拍板；问题悬空。

**无闭环**：问题记了，责任人不明、期限不明；下次评审还在。

**不复盘**：同类问题在不同项目重复；经验没沉淀。

**课程**：评审质量，取决于“敢不敢说不”和“有没有人跟”。

#### 23.5.4 设计规范怎么沉淀

**来源**：评审问题/测试失效/返修案例/客诉。

**形式**：一条条“必须/禁止/推荐”，配图/算例；不要写成论文。

**例子**：“每个电源脚必须有 0.1μF，靠近引脚 ≤2mm”“BOOT0 必须有下拉，禁止悬空”“RS485 从站必须留终端焊盘”。

**评审**：新规范进清单；下次评审逐条对照。

**更新**：每季度/每项目复盘后更新；版本化。

**课程**：规范是“把踩过的坑变成别人的护栏”。

#### 23.5.5 评审 KPI：怎么衡量评审有没有用

**前置指标**：材料齐全率、按时评审率、清单覆盖率。

**过程指标**：问题数/严重度分布、平均时长、结论明确率。

**结果指标**：打样返工率、首板成功率、批量不良率、客诉数。

**滞后指标**：返修成本、项目延期天数。

**用法**：不追求“问题越多越好”，而看“高严重度问题是否前置发现”。

**课程**：评审的最终 KPI 是“少返工”，不是“多开会”。

#### 23.5.6 小团队怎么落地

**一人多角**：设计者不能自评；找同事/朋友交叉看，哪怕只问 10 个问题。

**简化清单**：保留“电源/时钟/复位/接口/保护/生产”六块，其余按项目加。

**时间**：30～60 分钟；线上/线下都行。

**记录**：一页纸+问题表；共享文档。

**节奏**：每个门禁一次；不追求“大而全”。

**课程**：小团队也能评审，关键是“有人敢提反对意见”。

#### 23.5.7 把评审嵌进项目计划

项目计划里如果只有“画图/打样/调试”，没有“评审”，评审就会被挤掉。正确做法是把五个门禁写成里程碑任务，给时间和人力：需求评审 0.5 天、原理图评审 0.5 天、PCB 评审 0.5 天、首板评审 0.5 天、量产评审 0.5 天。每个门禁前留 2～3 天自检/改图，门禁后留 1 天闭环。这样“评审”不是额外负担，而是计划的一部分；延期时先砍功能，不砍门禁。

**排期技巧**：评审放在打样下单前一天，逼着问题在付费前暴露；不要放在“有空的时候”。

#### 23.5.8 评审与供应链的交叉

很多“设计问题”其实是“供应链问题”：BOM 里的器件只有一家有货、交期 12 周、封装是冷门、替代料参数差很多。评审时要请采购/供应链参加，至少提供“交期/替代/价格”三项。关键器件（主控/电源/连接器/晶振）要确认“有替代、能买到、不是停产料”。否则设计通过、生产卡住，项目照样延期。

**检查**：BOM 每行是否有“替代料/交期/停产状态”；关键器件是否只此一家。

#### 23.5.9 被评审者的心态：把评审当“免费外脑”

设计者最容易把评审当成“挑错/否定”，于是提前防御、会上解释、会后抱怨。换个视角：评审是几个有经验的人免费帮你找问题，而且是在打样付费之前。被问到答不上来，不是丢脸，是“提前暴露知识缺口”；被指出错误，不是否定你，是否定“这个设计里的某个选择”。好的被评审者会提前列“我自己担心的三个点”，主动请人重点看；会把“我不知道”说出来，而不是编一个理由；会把问题记下来，而不是当场争输赢。

**做法**：评审前写一页“已知风险/待定项”，会上先讲；评审后把问题按 A/B/C 排序，先改 A 级。
### 23.6 测量与仿真

#### 23.6.1 评审记录模板（完整版）

| 字段 | 填写要求 | 示例 |
|---|---|---|
| 项目/版本 | 名称+版本号+阶段 | 控制板 V1.2 / 原理图评审 |
| 时间/地点 | 日期+会议形式 | 11-12 / 会议室 |
| 参会 | 角色+姓名 | 主持/设计/工艺/测试 |
| 材料 | 已发材料清单 | 原理图/PCB/BOM/测试 |
| 结论 | Go/Conditional/No-Go | Conditional |
| 条件 | 关闭项/责任人/期限 | R-01 张/11-15 |
| 高风险 | 安全/认证/核心功能 | 电源反接 |
| 签字 | 主持/决策 | 两人 |

**写法**：结论一句话；条件可验证；风险有接受人。

**归档**：按项目/阶段/版本命名；共享盘+Git 双备份。

#### 23.6.2 复盘会议模板

**会前**：发数据（进度/成本/测试/问题）；定议程；定时间盒。

**会中**：目标回顾（5 分钟）→结果对比（15 分钟）→差距原因（20 分钟）→改进项（15 分钟）→责任/时间（5 分钟）。

**会尾**：复述 3 条改进；确认下次检查时间。

**会后**：纪要 24 小时内发出；改进项进任务表。

**课程**：没有纪要的复盘，一周后就忘了。

#### 23.6.3 评审问题的分级处理

**A 级（安全/合规/核心功能）**：必须关闭才能 Go；不接受“下次改”。

**B 级（性能/可靠性/可生产性）**：Conditional；限期关闭；影响出货要评估。

**C 级（外观/丝印/文档）**：可接受/批量前改；记录。

**处理原则**：A 级一票否决；B 级看风险；C 级别浪费会议时间。

**课程**：分级不是“降低标准”，是“把注意力放在对的地方”。

#### 23.6.4 评审后的验证与关闭

**验证方式**：复测数据/波形/照片/第三方报告。

**验证人**：提问题的人或指定人；不能自己改自己验。

**关闭**：证据附在问题表；状态改“关闭”。

**复盘**：关闭后回看“这个问题的根因是什么/规范要不要改”。

**课程**：关闭不是“改完”，是“证明改好了”。

#### 23.6.5 评审数据怎么统计

每次评审记录：问题数、A/B/C 分布、关闭率、平均关闭天数、返工次数。按月/项目汇总，看趋势：A 级问题是否下降、关闭天数是否缩短、同类问题是否重复。数据不是为了考核个人，而是为了找“系统性弱点”：如果“封装错”反复出现，说明自查表/封装库有问题；如果“闭环慢”，说明责任/跟踪机制有问题。

**呈现**：一页图（问题数趋势+A 级占比+关闭天数），比十页文字更有说服力。

#### 23.6.6 复盘报告模板

**一页结构**：目标 vs 实际（进度/成本/质量）→ 做对的 3 条 → 做错的 3 条 → 根因（5Why）→ 改进项（责任人/时间）→ 需要支持。

**写法**：每条结论配数据/事实；不写“大家都很努力”；改进项要可执行、可检查。

**归档**：项目文档；下次复盘先看上次改进是否落地。

**课程**：复盘报告不是“总结”，是“下一阶段的输入”。

#### 23.6.7 会议纪要怎么写才有人看

**标题**：项目+阶段+日期。

**三段**：结论（Go/Conditional/No-Go）、条件（谁/何时/做什么）、风险（什么/影响/谁接受）。

**附件**：问题表/截图/数据。

**长度**：一页；重点加粗；不用流水账。

**发送**：24 小时内；抄送参会人+决策者。

**课程**：纪要是“执行依据”，不是“会议记录”。

#### 23.6.9 评审问题库：电源与时钟（20 问）

1. 输入电源范围写了吗？反接/欠压/过压各是什么行为？——没写范围，后面选型全靠猜。
2. 每路电源的负载清单和电流预算在哪？最坏情况是多少？——预算缺失是“上电就掉压”的头号原因。
3. Buck/LDO 的输入电容是多少、离引脚多远？——输入电容不够/太远，瞬态直接塌。
4. 电感饱和电流是否大于最大峰值？——饱和后电流飙升、芯片炸。
5. LDO 功耗算了吗？封装热阻多少、温升多少？——SOT-23 扛 0.5W 以上要警惕。
6. 每路电源有没有使能/上电时序？谁先谁后？——时序错会锁死/倒灌。
7. 电源好（PG）信号接了吗？复位是否等电源稳定？——PG 悬空会导致“时好时坏”。
8. 去耦电容每个电源脚都有吗？容值/位置是否合理？——0.1μF 要贴近引脚。
9. 模拟/数字电源是否分开？磁珠/0Ω 位置对吗？——混在一起噪声大。
10. 电源测试点有没有？能不能测到每路电压？——没有测试点，调试靠猜。
11. 晶振是无源还是有源？负载电容按多少算？——负载电容错会频偏/不起振。
12. 晶振下面是否避开走线/铺铜？——干扰/寄生电容。
13. 时钟输出走线多长？有没有串阻/端接？——长线振铃。
14. 复位电路是 RC 还是专用芯片？阈值/脉宽多少？——RC 在低温/慢上电会失效。
15. 复位按键会误触发吗？有没有滤波/ESD？——静电通过按键进芯片。
16. BOOT0/BOOT1 上电时是什么电平？有下拉吗？——悬空会进错启动模式。
17. 看门狗喂狗在哪个任务？卡死时能复位吗？——喂狗放在中断里等于没喂。
18. 调试口（SWD/JTAG）留了吗？会不会被外壳挡？——量产返修要靠它。
19. 时钟/复位有没有测试点？——波形看不到，问题定位不了。
20. 低功耗时时钟/电源怎么切？唤醒源是什么？——休眠漏电/唤不醒。

#### 23.6.10 评审问题库：接口与保护（20 问）

21. 每个接口的电平标准写了吗？3.3V/5V/RS232/RS485 是否混？——电平不匹配会烧。
22. 接口连接器定义（针序/方向）在哪？和线缆一致吗？——针序错会反接。
23. 有没有串阻/端接/共模电感？位置对吗？——端接位置错等于没接。
24. ESD 器件选了吗？结电容会不会影响信号？——高速线上大电容会“削”信号。
25. TVS 的钳位电压是否低于被保护器件耐压？——钳位太高等于没保护。
26. 浪涌/EFT 有没有考虑？保险丝/压敏电阻选型对吗？——工业场景常见。
27. 反接保护是二极管/MOS/理想二极管？压降/功耗多少？——二极管压降可能让后级欠压。
28. 过流保护是自恢复/一次性？动作电流多少？——选大了不起作用。
29. 接口地是怎么处理的？是否与主板地直连？——共地环路/浮地问题。
30. 隔离接口的隔离电源/隔离器选了吗？爬电距离够吗？——安规距离。
31. RS485 终端电阻/偏置电阻在哪？从站留了吗？——长线丢包。
32. CAN 终端 120Ω 怎么配？节点数多少？——终端多了/少了都通不了。
33. I2C 上拉多大？总线电容多少？——上拉过大上升沿慢。
34. USB CC/DP/DM 保护/串阻有吗？——静电/短路。
35. 网口变压器/ESD/终端电阻齐吗？——雷击/浪涌。
36. 天线/射频接口阻抗控制了吗？——50Ω 不是画得好看就行。
37. 连接器电流余量多少？端子压接方式？——大电流发热。
38. 线缆最长多少？信号速率/衰减够吗？——长线需要驱动/均衡。
39. 接口测试点/环回测试怎么接？——产测需要。
40. 接口不用时怎么处理（悬空/接地/配置）？——悬空输入会乱跳。

#### 23.6.11 评审问题库：PCB 与生产（20 问）

41. 板框/定位孔/连接器位置和结构图一致吗？——1:1 打印核对。
42. 叠层顺序/铜厚/阻抗写进 Gerber 说明了吗？——板厂按默认做会偏。
43. 电源线宽按电流算了吗？过孔数量够吗？——2A 至少 22mil/1oz。
44. 地去哪了？有没有跨分割？回流路径连续吗？——EMC/信号完整性根子。
45. 晶振/差分/高速线参考面完整吗？——跨分割会辐射/误码。
46. 差分对等长/等距/终端对吗？——USB/HDMI/网口。
47. 丝印 1 脚/极性/方向清楚吗？会不会压焊盘？——装配错。
48. 每个器件都有封装且核对过吗？——封装错是打样返工第一原因。
49. DRC/飞线清零了吗？未连接引脚怎么处理？——NC 要明确。
50. Gerber 逐层看过吗？阻焊/字符/钻孔对得上吗？——少一层就废。
51. 拼板方式/工艺边/Mark 点定了吗？——贴片机识别。
52. 钢网厚度/开孔按器件间距定了吗？——QFN/细间距。
53. 测试点直径/间距/位置够探针吗？——治具做不了。
54. 首件怎么测？AOI/X-Ray 覆盖哪些？——批量一致性。
55. BOM 有替代料/交期/停产状态吗？——缺料停线。
56. 极性器件（二极管/钽电容/LED）方向核对了吗？——装反炸。
57. 螺丝孔/接地焊盘/屏蔽罩位置对吗？——装配/EMC。
58. 板边器件离边够吗？V-CUT/铣槽影响吗？——分板应力。
59. 包装/静电防护/标签定了吗？——运输损坏。
60. 生产文件版本和图纸版本一致吗？——做错版本。

#### 23.6.12 复盘的时间线法

把项目从启动到结束画成一条时间线，标出关键节点（需求定稿/原理图/打样/首板/小批/量产）和每个节点发生的“意外”。然后逐个意外问：它是在哪个节点被发现的？如果早一个节点发现，成本差多少？为什么没早发现（没清单/没评审/没测试/没人）？这样复盘不靠记忆，而靠“事件—节点—成本”的结构。时间线法特别适合跨月项目，因为人对“哪一周发生了什么”记忆模糊，但对“打样回来那天发现什么”记得很清楚。

**输出**：一张时间线图+3 个“本可更早发现”的点+对应改进。

#### 23.6.13 5Why 的正确用法

5Why 不是“问五次为什么”，而是“沿着因果链问到可控的层面”。比如“板子烧了”→为什么？“MOS 短路”→为什么？“栅极过压”→为什么？“驱动电阻太小/米勒电容耦合”→为什么？“原理图沿用旧设计没核算”→为什么？“没有器件级评审清单”。问到“清单/流程”层，改进才是可复制的；停在“某人粗心”，改进只能是“下次注意”，等于没改。每问一层要有证据（波形/手册/记录），否则就是编故事。问到自己能改变的那一层就停，不必问到最后“宇宙为什么”。

**模板**：现象→直接原因→设计原因→流程原因→改进项（可执行）。

#### 23.6.14 仿真二：复位 RC 的延时与判据

评审常问“复位脉宽够不够”。用一个 RC 复位做仿真：10kΩ+100nF，时间常数 τ=1ms，从 0 到阈值约 0.7τ≈0.7ms；如果 MCU 要求复位低电平 ≥1μs 且电源上升 10ms，这个 RC 在电源慢上电时可能“复位跟着电源爬”，并不产生干净的低脉冲。仿真里把电源改成斜坡，观察复位脚波形，就能看出“RC 复位在慢上电下不可靠”，从而在评审里要求改专用复位芯片。

```circuitjs
rc-charge
```

**判据**：复位低电平持续时间、阈值电压、释放点是否在电源稳定之后；三者任一不满足，就是 A/B 级问题。

**课程**：仿真不是为了“好看”，是为了在评审桌上拿出波形，而不是“我觉得”。
#### 23.6.15 仿真一：用低通看“判据”的意义

评审里常说“这个电源纹波可以接受”，但“可以接受”不是判据。用 RC 低通（1kΩ+1μF，fc≈159Hz）做一次仿真：输入方波/噪声，观察输出衰减。它说明两件事：一是“滤波”只在特定频段有效，超过 fc 的噪声才能被压；二是“判据”必须写频段/幅度，否则“看起来干净”不等于“在 20MHz 带宽下纹波达标”。评审时把仿真波形和实测波形放在一起，讨论才有共同语言。

```circuitjs
rc-lowpass-159
```

**判据写法**：频段（DC～20MHz）、幅度（峰峰值）、条件（满载/最坏输入）、样本（3 块）。

**课程**：仿真不能替代实测，但能让评审从“感觉”变成“看曲线”。

### 23.7 常见坑

1. **只看原理图不看 PCB**：封装/布局漏。
2. **没有清单**：靠记忆漏项。
3. **问题不分级**：P0 和 P2 混一起。
4. **不写责任/验证**：改了没确认。
5. **评审太晚**：投板前才看。
6. **只挑错不给方案**：无法闭环。
7. **忽略 BOM/测试点**：生产/调试出问题。
8. **评审记录不归档**：下一版重犯。

#### 23.7.7 评审案例库（一）：电源与复位

**案例 1：输入电容离 LDO 太远。** 某板 12V 转 5V 再转 3.3V，3.3V LDO 输入电容放在板子另一头，中间走线 15mm。空载正常，一接无线模块就掉到 2.9V。评审时如果量一下“电容到引脚距离”，10 秒就能发现。规则：输入/输出电容离引脚 ≤5mm，地就近打孔。

**案例 2：LDO 功耗没算。** 5V 转 3.3V、负载 300mA，功耗 (5-3.3)×0.3≈0.51W；SOT-23 热阻约 250℃/W，温升超过 100℃。评审时算一下就会改成 SOT-89/加铜/换 Buck。规则：LDO 功耗 >0.3W 必须算热阻。

**案例 3：复位 RC 在慢上电时失效。** 某板用 10k+100nF 复位，电源上升时间 50ms，复位脚跟着电源慢慢爬，MCU 进入不确定状态。评审时问“电源上升时间多少/复位芯片阈值多少”，就能发现。规则：慢上电/宽温用专用复位芯片。

**案例 4：BOOT0 悬空。** 某 STM32 板 BOOT0 只画了测试点，没下拉；上电偶尔进 Bootloader，表现为“有时不跑程序”。评审时问“BOOT0 上电电平”，并要求 10k 下拉。规则：BOOT0 禁止悬空。

**案例 5：电源时序倒灌。** 某板 3.3V 先上、1.8V 后上，1.8V 器件 IO 通过上拉电阻给 3.3V 域“倒灌”，出现锁死。评审时看“每路使能/时序/隔离”，加时序控制或理想二极管。规则：多电源域必须写时序。

**案例 6：PG 悬空。** 某板 DC-DC 的 PG 没接，MCU 复位释放靠 RC；电源还没稳，MCU 先跑，偶发不启动。评审时问“复位是否等 PG”，把 PG 接到复位延时。规则：PG 要么用，要么明确 NC。

#### 23.7.8 评审案例库（二）：接口与保护

**案例 7：RS485 从站没终端。** 主站有 120Ω，从站没有；短线上没问题，拉到 30m 就丢包。评审时看“每个节点终端/偏置”，从站留焊盘可选。规则：终端按总线两端配置，偏置只在一处。

**案例 8：TVS 结电容太大。** 某 USB 2.0 线上用大结电容 TVS，眼图闭合、识别不稳。评审时问“结电容多少/速率多少”，换低电容型号。规则：高速线 TVS 结电容 <1pF 量级。

**案例 9：ESD 只打电源。** 某产品接口能过 ±4kV 接触，但空气放电打外壳缝隙时死机；原因是信号线没防护/地不连续。评审时看“ESD 打哪里/地怎么走”，补 TVS/地缝合。规则：ESD 要按“最可能打到的位置”设计。

**案例 10：反接二极管压降。** 12V 输入用二极管防反，压降 0.7V，后级 Buck 输入最低 10.5V，接近欠压点；冷启动时掉压复位。评审时算“最坏压降+欠压阈值”，改 MOS 理想二极管。规则：防反器件压降要进最坏计算。

**案例 11：I2C 上拉过大。** 4.7k 上拉、总线电容 300pF，上升时间约 1.4μs，快速模式 400kHz 下勉强；再加两个从站就出错。评审时算 `t_r≈0.8RC`，改 2.2k/减小电容。规则：上拉按速率/电容算，不抄默认。

**案例 12：连接器针序反。** 原理图按“1 脚方焊盘”画，实物连接器 1 脚在另一端；线缆做出来电源接反。评审时看“连接器手册针序+实物照片”，并要求 1:1 打印。规则：连接器必须对实物核对。

#### 23.7.9 评审案例库（三）：PCB 与 EMC

**案例 13：地跨分割。** 某 4 层板把模拟地/数字地分成两块，ADC 跨分割走线，采样噪声大 20 倍。评审时看“地被什么切开/回流路径”，改成单点连接/桥接。规则：信号线下方参考面必须连续。

**案例 14：电源线太细。** 2A 输出只画 10mil，满载压降 0.4V、发热明显。评审时按 `I=kΔT^0.44A^0.725` 算，2A/10℃/1oz 约 22mil。规则：电源线宽进评审表。

**案例 15：过孔不够。** 2A 只放 1 个 0.3mm 过孔，孔壁温升高、压降大。评审时算“每孔载流约 1A”，至少 2～3 个。规则：大电流过孔阵列。

**案例 16：晶振下方走线。** 晶振正下方走了 SPI 时钟，频偏/起振不稳。评审时看“晶振禁布区”，挖空/避开。规则：晶振下方不走线、不铺铜。

**案例 17：差分对不等长。** USB 差分差 8mm，高速时误码。评审时看“差分对长度差/间距”，控制在 5mil 内。规则：差分等长进 DRC/检查表。

**案例 18：丝印压焊盘。** 丝印压到 0402 焊盘，贴片后立碑/偏移。评审时 1:1 打印看丝印，挪位。规则：丝印离焊盘 ≥0.15mm。

**案例 19：测试点被器件挡。** 测试点放在屏蔽罩下/连接器后，探针够不着。评审时用治具模拟，挪到板边/空区。规则：测试点直径 ≥1mm、间距 ≥2.54mm。

**案例 20：板边器件太近。** 连接器离板边 0.5mm，分板时应力拉裂焊盘。评审时看“器件离边距离/拼板方式”，加工艺边。规则：器件离 V-CUT ≥1mm。

**案例 21：Mark 点被阻焊盖。** 贴片机识别不到 Mark，贴偏。评审时看 Gerber 阻焊层，Mark 开窗。规则：Mark 点周围 2mm 无阻焊/无铜。

**案例 22：拼板无工艺边。** 板边直接 V-CUT，轨道夹不住。评审时加 5mm 工艺边+Mark。规则：拼板按贴片机要求。

**案例 23：屏蔽罩接地不够。** 屏蔽罩只有 2 个焊盘接地，屏蔽效果差。评审时看“屏蔽罩地过孔/焊盘”，沿边多点。规则：屏蔽罩每边至少 2 个接地。

**案例 24：ESD 地环路。** 接口地与数字地长距离连，ESD 电流穿过 MCU。评审时看“地分割/单点”，加 TVS 就近泄放。规则：ESD 电流不穿敏感电路。

#### 23.7.10 评审案例库（四）：生产与测试

**案例 25：BOM 封装错。** 原理图 0805，BOM 写 0603，贴片后焊盘不匹配。评审时逐行对“封装/位号”，用 BOM 工具校验。规则：BOM 与原理图封装双向核对。

**案例 26：极性电容反。** 钽电容极性画反，上电短路。评审时看“极性标记/丝印/封装”，1:1 核对。规则：极性器件单独列表。

**案例 27：Gerber 缺阻焊层。** 出 Gerber 漏了阻焊，板厂按默认做，焊盘全开。评审时逐层对照层叠表。规则：Gerber 逐层签字。

**案例 28：钻孔与焊盘偏。** 钻孔文件原点与 Gerber 不一致，孔偏 0.3mm。评审时叠图检查。规则：钻孔/Gerber 同原点。

**案例 29：钢网开孔太大。** QFN 散热焊盘开孔 100%，锡量过多、芯片浮起。评审时按面积比 50%～80% 开孔。规则：细间距钢网开孔进工艺评审。

**案例 30：首件没测。** 小批直接生产，首件没签字，批量偏移。评审时确认“首件测什么/谁签”。规则：首件不签不批量。

**案例 31：测试判据太松。** 只测“能亮”，不测电流/纹波；坏板流到客户。评审时把判据量化。规则：判据必须数字/波形。

**案例 32：测试样本太少。** 1 块板通过就放行，批次问题没暴露。评审时按风险定样本（3～5 块）。规则：样本量与风险匹配。

**案例 33：老化没做。** 早期失效在客户手里出现。评审时加 24～48h 老化/温循。规则：新产品必须老化。

**案例 34：夹具压坏板。** 探针压力过大，测试时压裂焊盘。评审时看“探针行程/支撑”。规则：夹具要有限位/支撑。

**案例 35：包装不防静电。** 板子装普通塑料袋，运输后 ESD 损伤。评审时用防静电袋/托盘。规则：包装进生产清单。

**案例 36：版本不一致。** 生产文件 V1.1，图纸 V1.2，做错版本。评审时核对“文件版本/日期/签字”。规则：生产文件单一版本源。

#### 23.7.11 评审案例库（五）：流程与组织

**案例 37：评审前没发材料。** 会上才第一次看到图，大家只能“跟着翻页”，提不出深入问题。规则：提前 3 天发材料，标注重点页。

**案例 38：评审人不对。** 只有硬件参加，结构和工艺没来；连接器高度、拼板问题没人提。规则：按项目类型定参会角色。

**案例 39：主持人没控场。** 一个问题讨论 40 分钟，后面高风险项没时间看。规则：每个问题限时 10 分钟，超时转任务。

**案例 40：设计者防御。** 被提问题就解释“这是客户要求/以前都这样”，讨论变成辩论。规则：设计者只讲事实/数据，不辩护。

**案例 41：领导提前定调。** “我看没问题，下一个”，评审人不再发言。规则：技术结论先于资源决策。

**案例 42：结论模糊。** 记录写“基本通过，后续优化”，没有人知道到底能不能打样。规则：只允许三种结论。

**案例 43：问题没责任人。** 写“硬件组跟进”，实际没人跟。规则：责任人必须是具体人。

**案例 44：期限写“尽快”。** 两周后还在“尽快”。规则：期限必须是日期。

**案例 45：关闭没证据。** 说“改了”，但没复测/没截图。规则：关闭必须附证据。

**案例 46：不跟踪。** 问题表建了，没人过；下次评审同样问题还在。规则：每周 15 分钟过表。

**案例 47：复盘变追责。** 主持人问“谁的责任”，真因被藏。规则：对事不对人，先数据后结论。

**案例 48：复盘无输出。** 聊了两小时，没有改进项。规则：必须产出 3 条改进+责任人+时间。

**案例 49：经验不归档。** 同样的问题在下一个项目重复。规则：问题→规范/检查表。

**案例 50：评审记录丢失。** 三个月后查不到当时结论。规则：记录归档+版本命名。

**案例 51：变更不重评。** 打样前临时换器件，封装/参数没核对，板子回来不能焊。规则：变更走 ECO/重评。

**案例 52：门禁可跳。** “这次赶时间，先打样再说”，结果返工两次。规则：跳门禁要书面批准。

**案例 53：评审变批斗。** 评审人语气攻击，设计者以后隐瞒问题。规则：对事不对人，提问题带方案。

**案例 54：只评审不测试。** 图纸通过，但没人验证；首板一堆问题。规则：评审+测试两条腿。

**案例 55：只测试不评审。** 靠打样试错，周期长/成本高。规则：能在图纸上发现的，不要留到打样。

**案例 56：小团队不评审。** “就我一个人，评什么”，结果封装错/电源不够。规则：找外部人交叉看 10 个问题。

**案例 57：评审时间太长。** 4 小时会议，大家疲劳，后半段没人认真。规则：拆成 2 场/每场 90 分钟。

**案例 58：评审没有清单。** 想到哪看到哪，漏掉电源/时钟。规则：清单+动线。

**案例 59：评审没有优先级。** 丝印和电源余量一起讨论，高风险被稀释。规则：先 A 级后 C 级。

**案例 60：评审后不更新图纸。** 问题记了，图没改，下次还错。规则：关闭前必须改图/改文件。

#### 23.7.12 项目复盘：4 层板的两次改版

某 4 层板第一版：电源层被信号线切得零碎，DDR 走线跨分割，跑高负载时偶发死机。首板评审只看了功能，没有看“地/电源完整性”，结论 Go；小批后死机率 3%。第二版重新叠层（电源完整地平面、DDR 参考面连续），问题消失，但成本增加 15%。复盘结论：第一版省下的评审/仿真时间，远小于改版+客诉成本；门禁 3 应增加“参考面连续性”检查。

**教训**：4 层板的地/电源规划要在布局前定，不要“画完再补”。

#### 23.7.13 项目复盘：6 层板为什么一次成功

另一个 6 层板项目，首板一次通过，小批不良 <0.5%。复盘发现三个关键动作：一是需求阶段就把“环境/EMC/成本”写进验收；二是原理图和 PCB 各做了一次 90 分钟评审，问题全部闭环；三是首板 Bring-Up 按十步记录，异常 2 小时内定位。没有“神级设计”，只有“每个门禁都真的过了”。这说明评审的价值不是“保证不出问题”，而是“把问题留在便宜的地方”。

**可复制点**：需求验收表、两次评审、Bring-Up 记录表；这三样比“高手”更可靠。
